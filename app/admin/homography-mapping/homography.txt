## 1. **Overall Mapping Logic and Flow**

This page is for **homography mapping**: mapping points from a camera view (perspective) to a top-down map (plan view) of a mall. This is crucial for applications like people/object tracking, where you want to know where something seen in the camera is located on the map.

**The main flow:**
- **Select a camera** (from a list of cameras for the mall)
- **Create a zone** (e.g., a region of interest like "Checkout Counter")
- **Map the zone**: Select corresponding points on the camera frame and the map image to define the zone.
- **Add objects**: For each zone, you can add objects (e.g., "Shelf A") and map their positions by selecting points on both views.
- **Save the mapping**: The selected points are normalized and sent to the backend for storage and further processing.

## 2. **Frames Side by Side & Scaling Logic**

### **How the frames are displayed:**

- The UI shows the **mall map** and the **camera frame** side by side, each taking 50% of the width.
- Both are inside a flex container with a fixed aspect ratio (`32/9`), ensuring they are always side by side and proportionally sized.

### **Scaling Logic:**

- **Images are displayed with `object-fit: contain`**. This means the image will scale to fit the container while maintaining its aspect ratio, possibly leaving empty space (letterboxing).
- The code keeps track of the **natural size** of the images (`mallMapNaturalWidth`, `mallMapNaturalHeight` for the map).
- When a user clicks on the image to select a point, the code calculates the **actual image coordinates** (not just the click position in the container) by reversing the scaling and offset applied by the browser.

#### **Key scaling code:**

```ts
const rect = img.getBoundingClientRect();
const scaleImg = Math.min(rect.width / naturalWidth, rect.height / naturalHeight);
const displayWidth = naturalWidth * scaleImg;
const displayHeight = naturalHeight * scaleImg;
const offsetX = (rect.width - displayWidth) / 2;
const offsetY = (rect.height - displayHeight) / 2;
x = (event.clientX - rect.left - offsetX) / scaleImg;
y = (event.clientY - rect.top - offsetY) / scaleImg;
```

- **`scaleImg`**: How much the image is scaled down to fit the container.
- **`offsetX`/`offsetY`**: If the image doesn't fill the container, this is the empty space on the sides/top.
- **`x`/`y`**: The click position, adjusted for both the offset and the scale, to get the true image coordinates.

## 3. **Point Selection, Scaling, and Re-scaling**

### **Point Selection:**

- When you click on the camera or map image, the code:
  - Gets the click position relative to the image container.
  - Adjusts for any scaling and offset (see above).
  - Stores the resulting coordinates as a point in the original image's coordinate system.

### **Storing Points:**

- Points are stored as `{ x, y }` objects, where `x` and `y` are in the **original image's pixel space** (e.g., 1280x720 for the camera, whatever the map's natural size is).

### **Re-scaling for Backend:**

- Before sending to the backend, all points are **normalized to a standard size** (1280x720).
- This is done using the `toImageCoords` function, which reverses the display scaling to get the original image coordinates.

#### **Example:**

```ts
const src_points = mapping.src_points.map(p => {
  const pt = toImageCoords(p, camImg, camImg?.naturalWidth || 1280, camImg?.naturalHeight || 720);
  return [pt.x, pt.y];
});
```

- This ensures that, no matter how the image was displayed/scaled in the browser, the backend always receives points in the correct, original image space.
